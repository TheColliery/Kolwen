# governance/

One file per control family, each stating what is TRUE today with its backing, and what is
planned. The point is the shape: the controls and their documents exist from the start, so an
audit later gathers evidence instead of commissioning work.

| file | family |
|---|---|
| `policies.md` | the standing rules this repository is actually run under |
| `risk-register.md` | risks named, with what is done about each |
| `inventory.md` | assets, vendors and sub-processors |
| `access-control.md` | who can change what |
| `logging.md` | what is recorded, and where |
| `incident-response.md` | what happens when something goes wrong |
| `retention-deletion.md` | what is kept, for how long, and how it goes away |
| `change-management.md` | how a change reaches production |
| `ISO-MAP.md` | those files mapped to ISO/IEC 27001:2022 and ISO/IEC 42001:2023 control numbers |

**None of this is a certification, and none of it says "compliant".** A map of documents to
control numbers is a map.
